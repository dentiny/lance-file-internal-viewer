# Contributing

Bug reports with a link to the Lance file that misbehaves are the most useful thing you can send.

## Setup

You need Node 22 or newer.

```sh
npm install
npm run dev          # http://localhost:5173
```

Open `http://localhost:5173/?url=sensors.lance` to load the bundled example, or paste any Hub file URL.

## Before opening a pull request

```sh
npm run verify       # lint, type-check, unit tests, build
npm run test:e2e     # browser tests (first run: npx playwright install chromium)
REMOTE=1 npm test    # also parse a few real files on the Hugging Face Hub
```

`npm run format` fixes formatting and autofixable lint errors.

## Where things live

| Path                          | What it does                                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/lib/lance/`              | Everything about the file, with no UI. Start here for parsing bugs.                                                                                                  |
| `src/lib/lance/metadata.ts`   | Reads the footer, both offset tables, every column's metadata and the schema in global buffer 0.                                                                     |
| `src/lib/lance/encoding.ts`   | Decodes page and column encodings (`lance.encodings` for 2.0, `lance.encodings21` for 2.1+) into trees, and names each page buffer.                                  |
| `src/lib/lance/schema.ts`     | Maps schema fields to physical columns (every field in 2.0, leaves in 2.1+) and renders the schema.                                                                  |
| `src/lib/lance/model.ts`      | Lays out every byte range in the file.                                                                                                                               |
| `src/lib/inspector.svelte.ts` | The loaded file plus the user's selection (column, page, popover). Components read it from context.                                                                  |
| `src/lib/popover.ts`          | What the popover says about each kind of byte range.                                                                                                                 |
| `src/lib/paint.ts`            | Canvas helpers for the file strip: per-pixel dominant color and hit testing.                                                                                         |
| `src/components/`             | One Svelte 5 component per section of the page.                                                                                                                      |
| `tests/`                      | Vitest tests that load real Lance files from `public/` and `tests/fixtures/`, and compare them with what Lance's own reader reported when the fixtures were written. |
| `e2e/`                        | Playwright tests against the production build, on desktop and mobile viewports.                                                                                      |

The protobuf field numbers in `src/lib/lance/` come from `protos/file2.proto`, `protos/file.proto`, `protos/encodings_v2_0.proto` and `protos/encodings_v2_1.proto` in the [Lance repository](https://github.com/lance-format/lance/tree/main/protos).

## Conventions

- Svelte 5 runes (`$state`, `$derived`, `$props`) only.
- Lance logic goes in `src/lib/lance/` as plain functions with a test on a real file, not in components.
- Styles are scoped to their component. Shared colors, radii and fonts are CSS variables in `src/app.css`.
- Test fixtures are generated by `uv run scripts/make-fixtures.py`, so they can be rebuilt instead of hand-edited.
